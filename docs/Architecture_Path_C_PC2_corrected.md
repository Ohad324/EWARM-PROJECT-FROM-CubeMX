# Voice Recorder — Current Architecture (Path C-PC2-corrected)

**Date:** 2026-04-28
**Status:** ✅ **Working — real PCM data flowing into `s_DfsdmBuf`.** Path B retired; SAI4 retired (`#if 0`'d in source).

---

## 1. One-paragraph summary

The MP34DT05-A PDM microphone is driven by a 2.000 MHz clock generated by **DFSDM1 Channel 0**, which routes that clock out **PC2 / AF6 (DFSDM1_CKOUT)** through a flying wire to the mic CLK pin. The mic returns its 1-bit PDM data on **PC1 / AF3 (DFSDM1_DATIN0)**, which feeds back into **the same Channel 0**. Channel 0 samples DATIN0 against the *same internal CKOUT edges* that it drives out PC2 — so sample edge and drive edge share one silicon node, and clock drift between mic and sampler is impossible by construction (AN5027 §2.4.2). **Filter 0** (Sinc³, OSR=125) decimates the 2 MHz PDM stream to 16 kHz PCM and DMA-streams it into `s_DfsdmBuf[128]` at `0x30004000` (D2 SRAM1). SAI4 is no longer used.

## 3. Why this topology (vs. earlier paths)

| Path | Clock master | Mic data pin | Status |
|------|-------------|-------------|--------|
| A "Holy" (commit 6ebe0bf) | SAI4 PDM master on PE2/AF10 | PC1/AF6 (assumed DATIN1) | Clock validated on scope, data path **never produced real PCM** — AF6 mapping was wrong |
| B  | SAI4 → PE2 → wire → PC2/AF3 (DFSDM_CKIN1) | PC1/AF6 | Wire was broken — PC2 never received clock |
| **C-PC2-corrected** ★ | **DFSDM CH0 → PC2/AF6 (CKOUT)** | **PC1/AF3 = DATIN0** | **Active.** Single peripheral, single channel, clock and sample edge share one silicon node |

**The earlier silent failures were caused by a single mismapping:**

| Pin/AF | Source claim | Actual silicon mapping |
|--------|------------------|----------------------|
| PC1 / **AF3** | unused / CKIN1 (per CubeMX) | **DFSDM1_DATIN0** ← correct, confirmed by 3 web sources + silicon test |
| PC1 / AF4 | DATIN0 (Gemini) ❌ | I2C3_SCL — wrong |
| PC1 / AF6 | DATIN1 (project docs) ❌ | DATIN4 (channel 4 — unused) — wrong |

Code that wrote `GPIO_AF6_DFSDM1` to PC1 was actually routing the mic data to **channel 4**, not channel 1. The DFSDM filter, configured to read channel 1, then sampled an unrouted/floating DATIN1 line as constant 0, and Sinc³ OSR=125 saturated to **−30518 = `0xFF88CA01`**. This single AF byte explains months of "clock works but no audio."

Switching to **PC1 / AF3 → DATIN0** routes the data correctly and makes Channel 0 do double duty as clock master and data sampler — the simplest possible topology.

## 4. Register / pin reference

### GPIO

| Pin | AF | Mode | Pull | Speed | Role |
|-----|----|------|------|-------|------|
| PC1 | **AF3** | AF push-pull | NoPull | LOW | DFSDM1_DATIN0 (mic PDM data input) |
| PC2 | AF6 | AF push-pull | NoPull | VERY_HIGH | DFSDM1_CKOUT (drives mic CLK via wire) |
| PE2 | (Analog reset) | — | — | — | unused; SAI4 retired, stays high-Z |

### DFSDM Channel 0

| Field | Value | Meaning |
|-------|-------|---------|
| `DFSDMEN` | 1 | DFSDM peripheral enabled (CH0-only bit) |
| `CKOUTSRC` | 0 | CKOUT sourced from kernel clock (pclk2) |
| `CKOUTDIV` | 49 | pclk2 / (49+1) = **2.000 MHz** |
| `CHEN` | 1 | Channel 0 sampling enabled |
| `CHINSEL` | 0 | Read from own pin (DATIN0) |
| `PINSEL` | 0 | Standard pin selection |
| `SPICKSEL` | 01 | SPI clock = internal CKOUT (same edges driven out PC2) |
| `SITP` | 01 | Sample on falling edge (LR=HIGH mic data) |
| `DTRBS` | 6 | Right-shift by 6 → output fits int16 |
| Target `CHCFGR1` | `0x80310085` | DFSDMEN \| CKOUTDIV=49 \| CHEN \| SPICKSEL=01 \| SITP=01 |

### DFSDM Filter 0

| Field | Value | Meaning |
|-------|-------|---------|
| `DFEN` | 1 | Filter enabled |
| `RCH[2:0]` | 000 | Read from Channel 0 |
| `RCONT` | 1 | Continuous regular conversion |
| `RDMAEN` | 1 | DMA request on each sample |
| `FAST` | 1 | Fast mode |
| `FORD[2:0]` | 011 | Sinc³ |
| `FOSR` | 125 | Output rate = 2 MHz / 125 = **16 kHz** |
| Target `FLTCR1` | `0x20240001` | RCH=0 \| RDMAEN \| RCONT \| DFEN |

### DMA

- DMA controller: **DMA1**, **Stream 1**
- Request: DMAMUX1 channel 1, REQ ID = **101** (`DFSDM1_FLT0`)
- Direction: peripheral → memory
- Mode: circular, MINC, 32-bit P/M, priority high
- Source: `&DFSDM1_Filter0->FLTRDATAR` = `0x4001711C`
- Target: `&s_DfsdmBuf[0]` = `0x30004000` (D2 SRAM1, 128 × int32_t)
- Target `CR` = `0x0002551F`

### Clock & power gates (must be set)

| Register | Bit | Meaning |
|----------|-----|--------|
| `RCC_APB2ENR` (`0x58024450`) | 28 (DFSDM1EN) | DFSDM1 bus clock |
| `RCC_C1_APB2ENR` (`0x58024550`) | 28 (DFSDM1EN) | DFSDM1 access from CM7 core |
| `PWR_WKUPEPR` (`0x58024828`) | 5 (WKUPEN6) | **MUST be 0** — else WKUP6 hijacks PC1 |

## 5. Why DFSDM-as-master beats SAI4-as-master (synchronization)

For PDM, the data eye is roughly half a clock period. With CLK=2 MHz, that's 250 ns. Any drift between the clock that drives the mic and the clock that strobes the DFSDM sampler eats into that 250 ns budget.

- **SAI4-as-master:** SAI4 drives mic CLK from its own PLL-derived root; DFSDM samples PDM data using its `pclk2` kernel clock. The two roots diverge over time — measured `-2.34%` static error in this design — and the data eye drifts away from the sample edge over each frame.
- **DFSDM-as-master (current):** DFSDM Channel 0 generates internal CKOUT, drives it out PC2, *and* uses the same internal CKOUT to strobe its own sampler. The clock that leaves the chip and the clock that latches DATIN0 are the **same physical wire on the silicon die**. Drift is impossible.

This is exactly the AN5027 §2.4.2 "same source for clock-gen and decimator" rule, satisfied by sharing the source rather than by chasing a tight PLL relationship.

## 8. Recovery / revert paths

- **Revert PC1 AF only:** edit `stm32h7xx_hal_msp.c`, change `GPIO_AF3_DFSDM1` back to whatever earlier value, rebuild.
- **Re-enable SAI4-as-master:** in `main.c` change `#if 0` → `#if 1` around `MX_SAI4_Init();` and revert the DFSDM CH0 init back to clock-master-only. SAI4 init body is preserved verbatim in source.
- **Last-resort:** `git checkout HEAD -- CM7/Core/Src/main.c CM7/Core/Src/stm32h7xx_hal_msp.c` returns to the previous Path C-PC2 (uncorrected) firmware at commit `aaf0a5e`.
